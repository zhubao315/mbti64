> **产物**：`书-千分之一的你/装帧/mockup-*.jpg`

## 1. 为什么主图不能直接让 AI 画

电商主图必须和实物一致。封面上的「千分之一的你」「从16型到64型：人格画像、差异理解与成长练习」「朱宝 著」一个字都不能错。实测：

- `minimax-h3-image` 在第六卷扉页上写出「心理学书设第六卷扁」；
- 同一模型做 3D 立体化时，书脊上的竖排书名被改写成「封面你」「作者 音它」，副标题词序也换了。

而 `moss-image` **只支持文生图**（`/images/edits` 直接返回「图片编辑请用 minimax-h3-image」），没法拿真封面去做立体化。

## 2. 解法：AI 出环境，真封面贴回去

把「写实」和「文字准确」这两件事拆开，各交给擅长的那一侧：

| 部分 | 谁来做 | 为什么 |
|---|---|---|
| 透视、材质、光影、纸页厚度、投影、背景 | **moss-image** | 这正是 AI 比脚本强的地方 |
| 封面画面与全部文字 | **真实的 `封面.png` 透视贴图** | 逐像素一致，不会有错字 |

具体做法：

1. 让 moss 画一本**封面是纯色**的书（饱和青绿，H≈120）。其余全是白 / 灰 / 米白 / 木色，按色相就能把封面挑出来。
2. 检测出封面的四边形。
3. 把真实的 `封面.png` 透视变换贴回去，并按底图里的光照做明暗匹配。
4. 把封面板切口残留的底色改成纸质白；把纯色封面在台面上留下的青绿反光中和掉。

**书脊那一侧不要露出同色封面板**，否则那一窄条会跟封面连成一片，四边形会歪 —— 所以视角一律转成「右前方是纸页切口、书脊藏在背面」。

## 4. 检测与合成是怎么做的

**找封面**（`scripts/apply_cover.py`）

1. HSV 掩膜：色相落在青绿区间、饱和度够高 → 挑出封面（背景灰、纸页米白、桌面木色饱和度都低）。
2. 取最大连通区域。
3. 求凸包 → 两种拟合方式各出一个四边形，用**覆盖率**（四边形盖住了多少目标区域）选好的那个：
   - 「凸包内最大面积四边形」—— 对规整的四边形面（正面 / 封底）准；
   - 「按凸包主边方向求交点」—— 对弯曲的窄条（书脊）准，但会把封面板切口一起框进去。
4. 角点顺序：**左上 / 左下 / 右下 / 右上**。顺序错了不会报错，只会画出一个旋转 90° 的怪东西 —— 必须显式换。

**贴图与光照**

- 透视变换自己解单应矩阵（DLT，8 个未知数最小二乘）+ 双线性采样。PIL 的 `Image.QUAD` 语义不符合预期（源图整幅映射进整幅画布、框外全黑），不能用。
- 明暗匹配：底图里那块纯色封面本身就是「同一材质在同一光照下」的样本，它的亮度分布就是这张图该有的明暗。取亮度比值作为系数乘到真封面上。
- 明暗系数要存成图再取回时，**缩放满量程不能用 255**（系数可能 >1，`uint8` 会回绕成黑块）；用 200 当满量程。

**收尾**

- 封面板切口：纯色封面的切口也是那个纯色，换成真封面后会留一圈异色边 → 改色成纸质白。
- 纯色封面在台面上留的青绿反光 → 中和掉（真封面是白的，不会有绿反光）。
- 封面的 alpha **不要羽化**：羽化会让底图从半透明处透出来，在四周留下一圈底色的线。

## 5. moss-image 的脾气（实测）

- 端点 `http://219.142.87.233:18200/v1`，无鉴权，模型名 `moss-image`。
- 底层是 Flux2 架构：`moss_image_sft_bf16` 的 UNET + Qwen3.5-9B 的文本编码器 + `flux2-vae_small`；固定 30 步、cfg 3.0、euler/sgm_uniform。
- **支持 `negative_prompt`**（KSampler 有负向分支）—— 空白封面必须靠负面提示词压住它自带的 `moss_xvstyle,` 前缀（那个前缀会让它爱往书上放英文标题）。
- 请求 `2048x1536` 回来的是 **1632×1216**（服务端自己降的档）。
- 单张 50~200 秒。
- 端点上写 `model: "moss"` 之类的别的名字**不会报错**，会静默用 minimax-h3 出图 —— 别被骗。

## 6. 重新生成

```bash
# 全流程（重新生图 + 合成，约 8~12 分钟）
bash scripts/build-moss-mockup.sh

# 只重新生图（换 seed 或改提示词）
node scripts/gen-moss-mockup.mjs --only hero-3q

# 只重新合成（底图已存在时，41 秒跑完 9 张）
bash scripts/build-moss-mockup.sh --compose

# 单张调试
python3 scripts/apply_cover.py \
  --base assets-hifi/moss-mockup/hero-3q.png \
  --cover 书-千分之一的你/装帧/封面.png \
  --out /tmp/t.jpg --h-lo 100 --h-hi 145 --expand 1.5 --reach 45 --debug
```

依赖：`numpy` + `Pillow`（不需要 OpenCV；连通域、凸包、最大面积四边形都是自己实现的）。

## 7. 备用方案：确定性渲染

`scripts/render_book_mockup.py` 用纯几何建模算透视 / 光影 / 纸页 / 投影，把真封面贴上去 —— **不需要 AI、不需要网络、逐字节可复现**，质量偏「CG」但绝不出现 AI 痕迹。moss 服务不可用时用它顶上：

```bash
python3 scripts/render_book_mockup.py          # 4 个视角，2048×1536
python3 scripts/render_book_mockup.py --size 1536x1536   # 方形
```

## 8. 注意事项

- 装帧三件套（`封面.png` / `封底.png` / `书脊.png`）一旦重出，**必须重跑合成**，否则效果图里的书和实际印刷品会不一致。
- 书脊贴图不是原始 `书脊.png`：那条是「印刷拼版」（46×291mm），直接贴会把竖排书名压扁。合成前会用 `build_spine_texture()` 重排成书脊面比例（24mm×200mm）。
- 效果图里的书是「立着的」姿态，靠影子压住 —— 这是电商渲染的常见处理，不代表实物的真实摆放方式。
- 画面里的书没有做真实装订的曲面（书脊是平的折面）。在电商缩略图尺度上看不出差别。
